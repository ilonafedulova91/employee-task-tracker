# Employee Task Tracker

**Employee Task Tracker** — REST API для создания, распределения и отслеживания задач сотрудников. Приложение помогает менеджерам организовывать рабочие процессы, контролировать выполнение задач и управлять сроками, а сотрудникам — просматривать назначенные им задачи и обновлять их статус.

## Возможности проекта

- **Управление задачами:** создание, просмотр, редактирование и удаление задач.
- **Назначение исполнителей:** возможность назначать задачи сотрудникам.
- **Отслеживание статусов:** ожидание выполнения (`pending`), в процессе (`in_progress`), выполнено (`completed`).
- **Приоритеты задач:** низкий (`low`), средний (`medium`), высокий (`high`).
- **Разграничение прав доступа:** менеджеры управляют всеми задачами, сотрудники работают только с назначенными им задачами.
- **Фильтрация:** по статусу, приоритету и исполнителю.
- **Поиск:** по названию и описанию задачи.
- **Сортировка:** по дате создания, сроку выполнения и приоритету.
- **Документация API:** интерактивная документация Swagger на основе OpenAPI.
- **Контейнеризация:** запуск приложения и PostgreSQL с помощью Docker и Docker Compose.
- **Автоматизированное тестирование:** тесты с использованием Django REST Framework, pytest и pytest-cov.

## Установка и запуск

### Необходимые инструменты

Перед началом работы установите:

- Python 3.12
- Poetry
- Docker Desktop с поддержкой Docker Compose
- Git

### Вариант 1. Запуск через Docker Compose

Рекомендуемый способ запуска проекта.

**1. Клонируйте репозиторий:**

```bash
git clone git@github.com:ilonafedulova91/employee-task-tracker.git
cd employee-task-tracker
```

**2. Создайте файл переменных окружения:**

В Windows PowerShell выполните:

```powershell
Copy-Item .env.example .env
```

При необходимости отредактируйте `.env`, указав подходящие параметры подключения к базе данных и секретный ключ Django.

**3. Соберите образ и запустите контейнеры:**

```bash
docker compose up --build -d
```

Docker Compose запустит PostgreSQL, дождётся готовности базы данных, применит миграции Django и запустит приложение.

**4. Проверьте состояние контейнеров:**

```bash
docker compose ps
```

**5. Создайте учётную запись администратора:**

```bash
docker compose exec web python manage.py createsuperuser
```

**6. Откройте приложение:**

- Swagger UI: http://127.0.0.1:8000/api/docs/
- API задач: http://127.0.0.1:8000/api/tasks/
- Панель администратора Django: http://127.0.0.1:8000/admin/

Просмотр и изменение задач через API требуют аутентификации.

**Просмотр логов приложения:**

```bash
docker compose logs -f web
```

**Остановка контейнеров:**

```bash
docker compose down
```

Чтобы остановить контейнеры и удалить том с данными PostgreSQL, выполните:

```bash
docker compose down -v
```

> **Внимание:** команда `docker compose down -v` удаляет том базы данных и сохранённые в нём данные.

### Вариант 2. Локальный запуск

**1. Установите зависимости:**

```bash
poetry install
```

**2. Создайте файл `.env`** на основе `.env.example` и настройте параметры подключения к PostgreSQL.

**3. Запустите контейнер базы данных:**

```bash
docker compose up -d db
```

При локальном запуске Django подключается к PostgreSQL по адресу `127.0.0.1:5433`.

**4. Примените миграции:**

```bash
poetry run python manage.py migrate
```

**5. Создайте администратора:**

```bash
poetry run python manage.py createsuperuser
```

**6. Запустите сервер разработки:**

```bash
poetry run python manage.py runserver
```

API будет доступно по адресу http://127.0.0.1:8000/.

## API Endpoints

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/api/tasks/` | Получение списка доступных задач |
| `POST` | `/api/tasks/` | Создание задачи (только менеджер) |
| `GET` | `/api/tasks/{id}/` | Получение конкретной задачи |
| `PUT` | `/api/tasks/{id}/` | Полное обновление задачи (только менеджер) |
| `PATCH` | `/api/tasks/{id}/` | Частичное обновление задачи |
| `DELETE` | `/api/tasks/{id}/` | Удаление задачи (только менеджер) |
| `GET` | `/api/schema/` | Получение схемы OpenAPI |
| `GET` | `/api/docs/` | Интерактивная документация Swagger |
| — | `/admin/` | Панель администратора Django |

Аутентификация и разрешения настраиваются средствами Django REST Framework.

## Модель задачи

Каждая задача содержит следующие поля:

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор задачи |
| `title` | Название задачи |
| `description` | Описание задачи, необязательное поле |
| `status` | Статус: `pending`, `in_progress` или `completed` |
| `priority` | Приоритет: `low`, `medium` или `high` |
| `created_at` | Дата и время создания |
| `deadline` | Срок выполнения, необязательное поле |
| `assignee` | Идентификатор назначенного сотрудника |
| `created_by` | Идентификатор пользователя, создавшего задачу |

Поля `id`, `created_at` и `created_by` доступны только для чтения через сериализатор задачи.

## Фильтрация, поиск и сортировка

### Фильтрация

Получение задач с определённым статусом:

```text
/api/tasks/?status=pending
```

Фильтрация по приоритету:

```text
/api/tasks/?priority=high
```

Фильтрация по исполнителю:

```text
/api/tasks/?assignee=2
```

Использование нескольких фильтров одновременно:

```text
/api/tasks/?status=in_progress&priority=high
```

### Поиск

Поиск по названию и описанию задачи:

```text
/api/tasks/?search=report
```

### Сортировка

Сортировка по дате создания:

```text
/api/tasks/?ordering=created_at
```

Сортировка по сроку выполнения в обратном порядке:

```text
/api/tasks/?ordering=-deadline
```

Сортировка по приоритету:

```text
/api/tasks/?ordering=priority
```

Префикс `-` перед названием поля задаёт сортировку по убыванию.

## Права доступа

### Менеджер

Пользователь с флагом Django `is_staff=True` может:

- Просматривать все задачи.
- Создавать новые задачи.
- Изменять поля задач.
- Удалять задачи.

### Сотрудник

Авторизованный пользователь без флага `is_staff` может:

- Просматривать только назначенные ему задачи.
- Изменять статус назначенной ему задачи.
- Не может создавать задачи или изменять остальные поля задачи.

Сотрудник не может получить задачу другого сотрудника через API.

## Переменные окружения

Для настройки приложения используется файл `.env`.

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | Секретный ключ Django |
| `DEBUG` | Включение или отключение режима отладки |
| `ALLOWED_HOSTS` | Список разрешённых хостов через запятую |
| `DB_NAME` | Название базы данных PostgreSQL |
| `DB_USER` | Пользователь PostgreSQL |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL |
| `DB_HOST` | Адрес сервера базы данных |
| `DB_PORT` | Порт PostgreSQL |

При запуске через Docker Compose приложение подключается к базе данных по имени сервиса `db` и порту `5432`. При локальном запуске Django использует `127.0.0.1:5433`.

> **Безопасность:** не добавляйте файл `.env` в Git. Для рабочего окружения используйте уникальный секретный ключ Django и надёжные пароли базы данных.
